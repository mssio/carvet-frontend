# CarVet frontend: React conversion design

Date: 2026-10-25
Source mockup: https://github.com/mssio/carvet-mockup (static HTML/CSS/JS, commit `2d4e53e`)
Target repo: this one (`carvet-frontend`, currently a fresh Vite + React 19 + TypeScript scaffold)

## Intent

CarVet is a public website by Team Moneyball for estimating vehicle CO₂ emissions and fuel consumption, built on the Natural Resources Canada (NRCan) Fuel Consumption Ratings dataset (29,215 records, 1995–2026). The mockup proves the look and flow as four static HTML pages. This project turns it into a maintainable React app that teammates can keep building on, so that a later phase can connect the Predict page to a real prediction-model backend.

## Goals

1. Convert the four mockup pages to React with **React Router v8**, matching the mockup's look and behaviour:
   - `/` Home (`index.html`)
   - `/explore` Explore (`explore.html`)
   - `/predict` Predict (`predict.html`)
   - `/compare` Compare (`compare.html`)
2. Install every CSS/JS library the mockup uses from npm instead of CDNs or pre-compiled files (Tailwind, Chart.js, PapaParse, the three Google Fonts).
3. Make the site deployable to **Cloudflare Workers (static assets)** using Cloudflare's default build/deploy/preview commands unchanged.
4. Write `AGENTS.md` (generic, for any AI coding tool) and `README.md` for teammates.
5. Write a docs note telling the owner what to do in the Cloudflare dashboard.

## Non-goals (this phase)

- The prediction backend / model API. Predict keeps its mockup behaviour (example presets).
- Logins or any user accounts. Everything on the site is public and nothing is per-user.
- Regenerating the dataset-derived files when new model-year data (2027) appears. Later phase.
- Connecting Cloudflare (the owner does this by hand, following the docs note).
- Redesigning anything. This is a faithful conversion.

## Anti-goals (failure even if it "works")

- The React site looks or behaves noticeably different from the mockup.
- The Cloudflare build fails with the default commands (`npm run build`, `npm run deploy`, `npx wrangler preview`).
- AGENTS.md written for one specific tool (e.g. Claude-only conventions) so other tools/teammates can't use it.

## What the mockup contains (facts from reading it)

- **Pages:** four HTML files sharing a header (logo, nav Home/Explore/Predict/Compare, mobile menu toggle) and footer, delimited by `<!-- SHELL:HEADER -->` comments. Each `<body data-page="...">` runs `CarVet.pages.<page>()` from `assets/js/app.js`. Page `<title>`s: "CarVet · Home/Explore/Predict/Compare". A "Skip to content" link targets `#main`.
- **CSS:** `assets/carvet.css` is compiled **Tailwind v3.4.19** output (22 KB, minified). The Tailwind config is not in the repo. It contains a custom Material-style palette (e.g. `primary` rgb(13 99 27), `primary-container` rgb(46 125 50), `error` rgb(186 26 26), `surface-container*`, `secondary-container`, `inverse-surface`, `on-primary-container`), CO₂ band colours (`band-low/moderate/elevated/severe`), custom font-size/family utilities (`font-headline-lg`, `text-headline-lg`, `font-body-md`, `font-code`, …) and component classes (`card`, `chip`, `chip-low/moderate/elevated/severe`, `btn-primary`, `btn-secondary`, `nav-link`).
- **Fonts:** Google Fonts: Inter (400/500/600/700), JetBrains Mono (400/600), Plus Jakarta Sans (600/700/800).
- **Images:** `assets/img/logo.svg` (also the favicon), `car-sedan.svg`, `car-suv.svg`, `car-pickup.svg`, `car-van.svg`.
- **JS:**
  - `app.js`: pure helpers on `CarVet.*` (`toNumber`, `annualCost`, `annualCo2Tonnes`, `co2Band`, `fmt`, `fmtSigned`, `hashParam`, `pickPreset`, `compareDeltas`, …; a comment says they're unit-tested in `tests/js/app.test.js`, which is **not** in the repo) and page initialisers for home, predict, compare, explore. **Note:** `CarVet.pages.compare` in `app.js` is overridden by `compare.js` (loaded later on compare.html). The `app.js` version is dead code.
  - `charts.js`: a small hand-written **SVG** chart helper (`CarVetCharts`: histogram, line, scatter, columns, hbars, heatmap, `esc`). Used by Compare (`hbars`).
  - `explore-filters.js`: Explore's interactive filters and charts using **Chart.js 4.4.7** (bar/line/scatter) over the CSV loaded with **PapaParse 5.4.1** from `https://sait-r2.mss.io/carvet/mockup/combined-output.csv`.
  - `compare.js`: Compare page: cascading Year → Make → Model → Variant pickers over `CARVET_CARS`, up to 4 selected cars (colours `#2e7d32 #ba1a1a #1d4ed8 #b45309`), km/year and fuel-price inputs, SVG bar chart.
  - `icons.js`: an inline SVG icon set, injected into `<i data-icon="name">`.
  - `stats.js`: `window.CARVET_STATS`, generated by `scripts/compute_stats.py` (not in repo): `kpis`, `quality`, `domains`, `hist`, `yearly`, `byClass`, `byFuel`, `byCylinders`, `corr`, `fuelVsCo2`, `scatter`, `rareMakes`, `presets.predict`, `presets.compare`.
  - `cars.js`: `window.CARVET_CARS`, the 2021–2026 records (861 KB) for Compare.
- **URL state:** Predict reads `#preset=…&km=…&price=…` from the hash. The live Compare (`compare.js`) has **no** URL state. Only the dead `app.js` compare code read `#preset=…&km=…`.
- **Compare (Claude's call):** port only the live `compare.js` behaviour. Don't port the dead `app.js` compare page or `presets.compare` usage, and don't add URL state to Compare. `compareDeltas` is a pure helper: keep it in the helpers module with its test, even though no page uses it yet.
- `combined_output.csv` is also checked into the mockup repo, but the site loads the R2 copy.

## Decisions

### Decided with the owner
- React Router **v8** (the owner first asked for v7, then switched to v8 on 2026-10-25 after learning 8.x is the current major).
- No authentication.
- The backend (later) only runs the prediction model. The CSV is the only raw data source.
- Library list (below) approved.
- Cloudflare: follow Cloudflare's guidance for npm scripts. The owner connects the repo themselves. Provide a docs note.
- AGENTS.md must be tool-agnostic. Teammates will work in the repo.

### Architecture (Claude's calls, approved by the owner as part of the library plan)
- **React Router framework mode** with `ssr: false` and `prerender` for all four routes. The build output is static HTML + assets in `build/client`. No server code runs on Cloudflare.
- **Tailwind CSS v4** via `@tailwindcss/vite`, with the mockup's custom theme rebuilt as `@theme` tokens and the component classes (`card`, `chip*`, `btn-*`, `nav-link`) as `@layer components` / `@utility`, reconstructed from the compiled `carvet.css`. Every page is checked visually against the mockup, because v3 → v4 defaults differ (e.g. default border colour, ring width, `space-*` selectors). If parity becomes painful, falling back to Tailwind 3.4 is acceptable.
- **Data layer:** a single module (e.g. `app/lib/data.ts`) that every page reads through:
  - `stats.json` and `cars.json` (converted 1:1 from `stats.js` / `cars.js`) imported from the app.
  - the CSV URL for Explore (kept as the R2 URL, in one constant).
  - an **async** `predict(spec): Promise<Prediction | null>` function. For now it resolves to the preset record whose specs match the form exactly, or `null`. The model API replaces its body later without touching the page.

### Predict page behaviour (decided with the owner)
- **On load:** show the preset from `#preset=` (or the first preset) as a demo, exactly as in the mockup: form filled, results and running cost shown, without calling `predict`.
- **Picking a preset button:** same as the mockup (fill the form, show that preset's results).
- **Editing fields and pressing Predict:** call `predict(formValues)` with the current form values (controlled inputs). While pending, show a loading state on the button/results. On a result, show it and update the running cost. On `null`, show a clear "No estimate available yet for this vehicle" empty state in the results panel (running-cost outputs show "—"). On error, show an error message. Then scroll to results as the mockup does.
- This is the one intentional behaviour change from the mockup.
- Keep the existing **React Compiler** (babel preset) and **oxlint** setup if they work with the React Router Vite plugin. If the compiler conflicts, drop it and note why.

### Packages

Versions decided with the owner on 2026-10-25 (latest on npm that day; save as `^` ranges, lockfile pins exact). React Router uses **v8 (8.5.0, latest)**. v8 requires Node >=22.22.0 and React >=19.2.7 (this repo has React ^19.3.1; local Node is 24). Its peers accept Vite ^7||^8, TypeScript ^5.1–^7 and Wrangler ^4. v8 removed all `future.v8_*` flags (their behaviour is now default; `splitRouteModules` is a top-level config option, on by default). Follow v8 docs, not v7 examples. Pin the Node version for Cloudflare Workers Builds (e.g. `.node-version` with `22` or `24` plus `"engines": { "node": ">=22.22.0" }` in package.json), and mention it in the Cloudflare docs note.

### Cloudflare (per Cloudflare's Workers Builds docs, checked 2026-10-25)
- Workers Builds runs: **build command** `npm run build` on every push, **deploy command** `npm run deploy` (→ `wrangler deploy`) on the production branch (`main`), **preview command** `npx wrangler preview` on other branches (after "Builds for Preview branches" is enabled in Settings → Builds), giving a per-branch preview URL.
- Add `wrangler.jsonc`: `name: "carvet"` (Claude's call, changeable), a current `compatibility_date`, `assets.directory: "./build/client"`, and `not_found_handling` suited to prerendered pages (`404-page` with a real 404 route, or `single-page-application`; builder's choice, document it).
- npm scripts: `dev`, `build` (typecheck + `react-router build`), `preview` (local: serve the build, e.g. `wrangler dev` or `vite preview`), `deploy` (`wrangler deploy`), `typecheck`, `lint`, `test`. Verify `npx wrangler preview` works for an assets-only Worker with no `main`. If it needs adjustment, put the fix in config, not in the dashboard command.
- **R2 CORS:** Explore fetches the CSV cross-origin from `sait-r2.mss.io`. The bucket's CORS policy must allow the new site origins (production `*.workers.dev` / custom domain, preview URLs, and `localhost` for dev). Call this out in the docs note.

### Docs
- `docs/cloudflare-deploy.md`: step-by-step for the owner: import the existing GitHub repo (not the "create new repo" template flow), the three command fields to leave at their defaults, enabling preview branch builds, custom domain (optional), R2 CORS update, and how to deploy manually from a laptop (`npx wrangler login`, `npm run deploy`).
- `README.md`: what CarVet is, the pages, tech stack, setup (`npm install`, `npm run dev`), scripts, project structure, data sources (NRCan, Open Government Licence – Canada; R2 CSV; generated JSON), deployment pointer, and the roadmap (prediction API, 2027 data refresh).
- `AGENTS.md`: tool-agnostic instructions for AI coding agents: project overview, commands (install/dev/build/test/lint/typecheck), directory layout, conventions (Tailwind tokens not hex, data only through the data layer, generated JSON is not hand-edited, keep parity with the mockup), how to verify a change, and what not to do (no server-only features, so no `action`/`headers` exports under `ssr:false`). Also add a one-line `CLAUDE.md` that points to `AGENTS.md` (Claude's call, so Claude Code picks it up too).

## Acceptance

- `npm run build` succeeds and outputs prerendered HTML for `/`, `/explore`, `/predict`, `/compare` in `build/client`.
- `npm run test`, `npm run lint` and the typecheck pass.
- Each page, viewed side by side with the mockup (desktop and mobile width), matches in layout, colours, fonts and interactions: mobile menu, Predict presets + running-cost inputs + hash params, Compare pickers/add/remove/chart, Explore filters + Chart.js charts + CSV load.
- No CDN `<script>`/font links remain. All libraries come from npm.
- The builder runs `npm run deploy` only if the owner asks. Otherwise verify the build output with the local preview script.
